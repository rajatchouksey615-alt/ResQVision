# Documentation

This directory contains the revised requirements and system-design draft pending team approval, database design and implementation records, domain-service implementation notes, working conventions, and academic project notes for ResQVision. Documentation distinguishes implemented internal workflows from unimplemented APIs and external integrations.

## Index

- [requirements/](requirements/README.md): system specification, functional and non-functional requirements, use cases, permissions, traceability, scope, and constraints.
- [architecture/](architecture/README.md): system and component architecture, overview, data flow, trust boundaries, technology choices, and open decisions.
- [workflows/](workflows/README.md): end-to-end, AI, incident response, and role workflows.
- [database_design/](database_design/README.md): implemented local PostgreSQL/Django schema baseline, ERD, data dictionary, constraints, lifecycle, and transaction design.
- [api_documentation/](api_documentation/README.md): REST conventions, versioning, and error handling.
- [testing/](testing/README.md): project testing approach and case template.
- [security/](security/README.md): security baseline and documentation.
- [deployment/](deployment/README.md): future local development and deployment planning.
- [project_documentation/](project_documentation/README.md): academic project overview, objectives, scope, and team responsibilities.
- [decisions/](decisions/README.md): architecture decision records.
- [diagrams/](diagrams/.gitkeep): reserved for reviewed architecture and workflow diagrams.

Use relative links, date material decisions, identify assumptions, and update affected documents when implementation changes.
