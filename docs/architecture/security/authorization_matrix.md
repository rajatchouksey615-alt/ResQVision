# Authorization Matrix

**Decision status:** Recommendations only; no unresolved permission is granted by this matrix.  
**Runtime statuses:** `ENABLED` = an implementation path is available today; `BLOCKED` = route/service fails closed or no route exists; `PARTIAL` = supporting model/service exists but policy/contract is unavailable.  
**Policy decision statuses:** `APPROVED`, `PROPOSED`, `BLOCKED`, `NOT_APPLICABLE`, `UNRESOLVED`. No business authorization in the reviewed draft documents is marked `APPROVED`.

## Interpretation and Approval Notes

- `PROPOSED` can describe an existing enabled code path as a draft requirement implementation; it does not mean stakeholders approved the permission.
- `BLOCKED` describes a deliberately unavailable policy/route. A 503 policy-unavailable response is not an authorization grant or a resource-existence signal.
- Out-of-scope incident/assignment reads currently use scoped querysets and 404 concealment. Do not generalize that response to unresolved-policy routes, which return 503 before resource lookup.
- Source owner/operator is not an application role. Audit reader, location steward, evidence custodian, and designated reviewer are responsibility labels requiring a separately approved identity/group design.
